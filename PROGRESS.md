## Open issues

**OI-1 (M1): Validate lengths before calling liboqs.**
Every crypto wrapper (KEM, Signature) must check that public key, ciphertext, and signature byte-lengths match the values reported by the algorithm before passing buffers to liboqs. A short or empty input must raise a clear error, never reach the C library. Add a regression test that a short/empty public key is rejected at the wrapper layer (not inside liboqs), so a future liboqs version that adds its own check does not mask the regression. Prompted by GHSA-w696-4vrr-x6x3, which showed earlier liboqs silently zero-padded short inputs.

**OI-2 (M1): SLH-DSA-PURE-SHA2-128f sizes for the M1 size assertions.**
liboqs 0.16.0 exposes this algorithm as `SLH_DSA_PURE_SHA2_128F` (underscores). Use the PURE variant, not a PREHASH variant.
- Public key: 32 B
- Secret key: 64 B
- Signature: 17088 B
The M1 size-assertion test must check these values at runtime against `kem.length_public_key` / `sig.length_signature` etc. and stop with a clear error if the installed library disagrees.

**OI-3 (M0): CLOSED — project-local liboqs source build now in `.oqs/`.**
liboqs 0.16.0 (tag `0.16.0`, commit `5a1a854`) cloned into `.oqs-src/` and built with:
```
cmake -S .oqs-src -B .oqs-src/build \
  -DCMAKE_INSTALL_PREFIX=$PWD/.oqs \
  -DBUILD_SHARED_LIBS=ON \
  -DCMAKE_BUILD_TYPE=Release \
  -DOQS_BUILD_ONLY_LIB=ON \
  -DOQS_DIST_BUILD=ON
cmake --build .oqs-src/build --parallel 8
cmake --install .oqs-src/build
```
Installed to `$PWD/.oqs/lib/liboqs.dylib`. The Makefile exports `OQS_INSTALL_PATH=$(abspath .oqs)` for all targets so no manual export is needed. Smoke test confirms dylib path is `…/pqc-gateway/.oqs/lib/liboqs.dylib`. `~/_oqs/` is no longer used by this project.

## M5b deliverables (3 commits on m5b-rekey-link, 2026-11-09)

**m5b-01-proto** — `session.py`: `RekeyTrigger`, retransmit queue, `_prev_session_id` + `known_session_ids`, `_route_open` session_id+epoch guard.
**m5b-02-stack** — `gateway.py`, `peer.py`: 1-byte type prefix (§15 item 22), M5a handshake fix (loop on unexpected first message), light/full rekey triggers, retransmit drain, `_pending` flush on REKEY_ACK and full-rekey success, `_do_full_rekey` coroutine, `_handle_hs_message` on peer, epoch-254 guard, full-rekey switch-over via trial open.
**m5b-03-tests** — 13 `test_e2e_link.py` tests, 1 `test_handshake.py` regression, 1 T9 full-rekey span.

**Key implementation notes:**
- **legacy CAN traffic is periodic**: if the gateway sends no DATA after `promote_full_rekey()` (CAN bus quiet), the peer's `_fr_pending` is not consumed. Peer switches on the first CAN frame forwarded after the full rekey. Acceptable.
- **`_fr` kept alive after FINISHED_I** so cached HELLO_R can be served on retransmit. Lazily cleared when `_fr_session_id` leaves `_sm.known_session_ids` AND `_fr_pending` is None.
- **Full-rekey FINISHED_I retransmit**: if a retransmitted HELLO_I arrives after `_fr` has been lazily cleared, the peer cannot return the cached HELLO_R. The initiator's per-attempt deadline expires and triggers a new attempt. Acceptable edge case.
- **`RekeyTrigger` fields** must be loadable from TOML config by M7 (`configs/sessions/default.toml`).
- **Test 7 bug**: original test wrapped `gw_link_inner` with `_DropAllWhere(_is_hello_r)`, which had no effect (gateway never sends HELLO_R). Rewritten to wrap `peer_link_inner` (peer's outbound) so HELLO_R is actually dropped. Frames injected during the failed-attempt window are delivered on the old session before the full-rekey task is cancelled in `finally`.
- **Cross-test contamination**: wrapping `peer_link_inner` in test 7 also fixed a race condition where the second `request_full_rekey()` could promote the gateway to a new session before the peer received FINISHED_I for it, causing the peer to drop frames 2 and 3 as "unknown session".

## Resolved issues (m4-fixes, 2026-11-05)

Regression tests in `tests/unit/test_oi_regressions.py::TestOI4CounterExhausted`.

**OI-5: RESOLVED.**
Duplicate REKEY_REQ bypass is now gated on `_rekey_state in (ACK_SENT, GRACE)`. After grace expires (`_expire_grace()` sets state to IDLE), the stale cached REKEY_REQ is not resent. Regression test: `test_duplicate_req_not_resent_after_grace_expires`.

**OI-6: RESOLVED.**
`RekeyConfig` renamed `rekey_timeout_s` → `rekey_timeout_ms = 400` (integer milliseconds, no backoff). Added `__post_init__` validator: budget = `(rekey_timeout_ms/1000) × (rekey_max_retries+1)` must be strictly less than `grace_period_s` (skipped for `grace_period_s=0.0` test sentinel). Default budget: 0.4 × 4 = 1.6 s < 2.0 s. Regression tests in `TestOI6ConfigValidator`.

**OI-7: RESOLVED.**
Added `hash_name: str` abstract property to `KDF` interface (`interfaces.py`) and both providers (`HkdfSha256` → "sha256", `HkdfSha384` → "sha384"). Removed providers import from `keyschedule.py`.
